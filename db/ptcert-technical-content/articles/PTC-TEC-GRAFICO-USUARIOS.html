Login loop LightDM (VM original) — resolvido 2026-08-25

Confirmado no Linux original: a VM entrou em loop LightDM → autologin pos → sessão inicia → sessão termina → greeter → repetição.

Causa confirmada: ownership incorrecto de ficheiros de autoridade da sessão gráfica no HOME de pos:

  • /home/pos/.Xauthority estava root:root (0600) — LightDM: Failed to open X authority … Permission denied.
  • /home/pos/.ICEauthority estava root:root (0600) — .xsession-errors: xfce4-session: Unable to access file …/.ICEauthority: Permission denied.

Procedimento canónico de diagnóstico e correcção (Confirmado no Linux original):

  1. Aceder por terminal/SSH/MeshCentral.
  2. Verificar LightDM:
    systemctl status lightdm --no-pager -l
  3. Verificar ficheiros: 
    ls -la /home/pos/.Xauthority /home/pos/.ICEauthority /home/pos/.xsession-errors
  4. Consultar erros da sessão: 
    tail -n 120 /home/pos/.xsession-errors
  5. Se ownership incorrecto (root:root), corrigir apenas esses ficheiros: 
    chown pos:pos /home/pos/.Xauthority
chown pos:pos /home/pos/.ICEauthority
  6. Confirmar: 
    ls -l /home/pos/.Xauthority /home/pos/.ICEauthority
  7. Reiniciar apenas o gestor gráfico: 
    systemctl restart lightdm
  8. Resultado esperado: LightDM → autologin pos → XFCE → arranque automático do PTcert.

Não fazer: chown recursivo em /home/pos. Corrigir apenas os ficheiros afectados.

Confirmado no Linux original: o erro XIO: fatal IO error 11 … on X server ":0" foi consequência da queda da sessão, não a causa primária. Warnings PAM pam_kwallet / pam_kwallet5 também não foram a causa.
